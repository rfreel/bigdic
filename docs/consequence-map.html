180 proposed frontier positions and 72 domain positions. A term earns a place here by the change it could make in a bound task. Placement is a design hypothesis, not a claim of execution, authority, or measured effect.

Rules, counterexamples, and scope
Read the governing change first.

The lanes separate interventions, decision rules, constraints, witnesses, and failure labels. The “Bind” line names information needed before a term can do that job. These labels may share spelling or appear in multiple domains; that does not make the corresponding methods equivalent.

Conditional dominance requires the same task, admissible moves, protected requirements, and a comparison of effects and costs. The word list alone establishes none of those.

12 further cuts

Parametric additions. Each identifies a possible state change and a failure to guard.

Alternatives

DECISION-PARTITIONparametric extension

Change: Group live hypotheses by the acceptable actions they permit

Bind: Hypotheses, requirements, and acceptable-action set for each hypothesis

Failure: Shared action assumed without checking every live class

Frame

MINIMAL-UNSAT-COREparametric extension

Change: Expose the smallest contradictory subset of formal requirements

Bind: Formalized constraints and a solver or checkable derivation

Failure: Informal disagreement mislabeled a formal inconsistency

Decision

VALUE-OF-INFORMATIONparametric extension

Change: Compare the value of an observation with acting now

Bind: Actions, outcome model, probability or bounded uncertainty, utility and probe cost

Failure: A numerical estimate invented without a governing model

Representation

ABSTRACTION-REFINEMENTparametric extension

Change: Split a coarse class when a real counterexample shows it hides a needed distinction

Bind: Abstraction relation, counterexample, and preserved invariant

Failure: A new representation breaks an already established result

Reasoning

ASSUMPTION-CUTSETparametric extension

Change: Expose shared dependencies whose failure would defeat several derivations

Bind: Dependency graph, failure hypotheses, and a separating observation

Failure: Nominally independent answers share the same unsupported premise

Challenge

SEQUENTIAL-TESTparametric extension

Change: Bound repeated evidence collection with precommitted continuation and stop rules

Bind: Observation process, error targets, stopping rule, and decision threshold

Failure: Threshold changed after seeing interim results

Evidence

EVIDENCE-DEPENDENCY-GRAPHparametric extension

Change: Track correlated observations and the claims that depend on them

Bind: Raw observations, acquisition methods, and dependency edges

Failure: Several copies of one source counted as independent confirmation

Control

POLICY-INVARIANCEparametric extension

Change: Permit a common action across unresolved live states

Bind: Live states, admissible actions, protected constraints, and common acceptance

Failure: One live state makes the proposed action unsafe

Action

EFFECT-LEDGERparametric extension

Change: Reconcile planned, attempted, and observed external effects

Bind: Target revision, action identifier, tool receipt, and side effects

Failure: A retry duplicates an ambiguous external effect

State

INVALIDATION-CONEparametric extension

Change: Reopen only results dependent on the changed basis

Bind: Versioned dependency edges and exact source or contract change

Failure: An unrelated verified result is discarded or a dependent one survives

Verification

CHECKER-INDEPENDENCEparametric extension

Change: Test whether a checker shares the failure it is meant to catch

Bind: Claim, checker implementation, common failure hypotheses, and independent probe

Failure: Generated claim and generated checker agree for the same wrong reason

Closure

ROBUST-CLOSUREparametric extension

Change: Close a request when a checked acceptable result persists across live rivals

Bind: All live classes, common accepted output, residue, and reopen condition

Failure: A live rival changes the required output
