# Agent system implementation plan

This is a plan, not a completion ledger. P0 is a structural slice. No task-completion or long-term gain result is claimed. Each unchecked item needs a concrete artifact, an observation, and a scoped acceptance record.

## P0: inventory and access

- [x] P0.1 Compile 794 V2 rows and retain multiple contextual signatures.
- [x] P0.2 Add nine explicitly LOCAL words without fabricating source membership.
- [x] P0.3 Build offline level × frontier map with 803 clickable words and default proxy components.
- [x] P0.4 Offer exact lookup, bounded browse, and candidate-only request packets.
- [x] P0.5 Validate record identity, proxy recomputation, and no false authority or execution claim.
- [ ] P0.6 Inspect desktop and phone rendering, keyboard access, and link behavior in a real browser.
- [x] P0.7 Reconcile all 794 entries and 1,000 signature references against the pinned V2 draft and benchmark table with `scripts/verify_source.py`.
- [x] P0.8 Publish a separate parametric consequence map with conditional admission rules; do not present V2 family weights as an effectiveness order.

## P1: interpret intent into a typed program

- [ ] P1.1 Define versioned Task fields: request ID, original words, outcome, requirements, preferences, scope, authority, budget, and acceptance predicate.
- [ ] P1.2 Define Sense fields: source ID, operands, pre/postconditions, read/write effects, protected invariants, alternative senses, and failure route.
- [ ] P1.3 Reject malformed task and sense records, leaving missing information explicit.
- [ ] P1.4 Add candidate retrieval with source IDs, alternatives, and an explicit no-match state. Measure it against the current cue baseline.
- [ ] P1.5 Demonstrate two similarly worded cases requiring different outputs; retain both when the separator is unavailable.
- [ ] P1.6 Bind role, target revision, environment, and exact checked property before a move is admitted.
- [ ] P1.7 Define conditional MacroProgram, step inputs/outputs, dependencies, stop rule, and recovery branches.
- [ ] P1.8 Type-check composition and detect loss of mandatory requirements or live material rivals.
- [ ] P1.9 Produce a bounded agent packet: current state, missing evidence, next admissible action, effects, and stop/reopen trigger.
- [ ] P1.10 Acceptance: 30 frozen contrast pairs yield appropriate branches and zero fabricated execution claims.

## P2: carry out real actions

- [ ] P2.1 Separate ToolCapability from AuthorityGrant by actor, action, target, environment, and time.
- [ ] P2.2 Add a read-only adapter that records actual target and result; a proposed read produces no receipt.
- [ ] P2.3 Add a reversible artifact adapter with request IDs, precondition recheck, and observed side effects.
- [ ] P2.4 Reconcile ambiguous remote outcomes before retry; preserve partial effects.
- [ ] P2.5 Define checkers for exact property, version, scope, and method; preserve PASS, FAIL, INCONCLUSIVE, ERROR, and NOT_RUN separately.
- [ ] P2.6 Run one real request from intent through selected program to delivered, independently inspected artifact.
- [ ] P2.7 Kill the adapter at each step and confirm no false success or duplicate external effect.

## P3: accumulate capability

- [ ] P3.1 Add append-only events with stable IDs, parent hashes, actual attempts, effects, and receipts.
- [ ] P3.2 Rebuild all derived views from the event history and reject tampered or incomplete replay.
- [ ] P3.3 Define capability nodes with prerequisites, property, checker, versioned environment, and reopen condition.
- [ ] P3.4 Promote only a property-matched PASS; retain FAIL and inconclusive attempts as evidence.
- [ ] P3.5 Invalidate only dependents after a changed source, contract, model, tool, or environment.
- [ ] P3.6 Compute the reachable minimal unresolved shoreline; keep incomparable nodes separate.
- [ ] P3.7 Save scoped lessons as executable examples, counterexamples, or checkers rather than general advice.
- [ ] P3.8 Delete selector and chat state; test whether a fresh agent reconstructs and reuses the release.

## P4: optimize the controller

- [ ] P4.1 Bind task-specific hard constraints and a multiobjective vector; preserve the frontier without governing weights.
- [ ] P4.2 Track action cost, reversibility, side effects, information gain, and continuation value.
- [ ] P4.3 Compare finite-model decisions against exhaustive dynamic programming where a complete objective exists.
- [ ] P4.4 Include joint probes and order-sensitive actions, retaining greedy-policy counterexamples.
- [ ] P4.5 Contrast PREWALK forecasts with actual action receipts; forecasts never count as execution.
- [ ] P4.6 Apply DISINHIBITIZE only to unsupported self-restrictions, preserving real authority and task constraints.
- [ ] P4.7 Compare each retained macro to an ordinary-language equivalent; remove overhead without measured benefit.
- [ ] P4.8 Evaluate 0/30/90/180/365-day metrics in `docs/benchmarks.md`, including harms, costs, and reset lift.

## P5: make it effortless for an agent

- [ ] P5.1 Observe real sessions and count repeated reads, ambiguous errors, wrong turns, and user corrections.
- [ ] P5.2 Provide one bounded `next` packet; keep deep inspection available on demand.
- [ ] P5.3 Return a machine-readable failure reason, affected state, and concrete safe next move.
- [ ] P5.4 Derive the UI's tower, trace, and shoreline from canonical records, not copied prose.
- [ ] P5.5 Test a fresh agent's ability to answer: required result, known state, available move, discriminating observation, reusable asset.
- [ ] P5.6 Run complete regression and source audit, then publish a versioned release with exact claim scope.

**Immediate work:** P1.1–P1.3 using a real request that an assistant previously stopped at a proposal. Preserve the unsupported 'must prove universal optimality first' condition as a counterexample, then ensure the binder removes it while retaining real constraints. The existing cue router remains a baseline, not an autonomous worker.
